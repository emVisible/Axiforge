# ADR-016：AXS 叙事文本语言（文本为真相源）

**状态**：已采纳（v2 Phase N）
**日期**：2026-07-07
**关联**：ADR-005、ADR-012（曾裁决「结构化 schema 先行，文本语法后置」——本 ADR 兑现后置承诺）

> **现行效力**：本文定义 AXS 语法的部分仍有效；“文本为全局真相源、冲突时文本优先”已由 [ADR-025](./025-axs-peer-dual-view.md) 修订。当前语法权威是 `packages/axs`，AXS 与剪辑台为同一 Draft 的对等视图。

## 背景

VN 创作是高频文本产出。v1.x 的拖拽节点画布适合表达分支结构，但在具体创作时间占比上成为「长通勤」：每写一句对白都要点开节点面板。市场对标（Ren'Py 的 .rpy、Ink 的 .ink）证明**文本优先**是叙事创作的效率上限。

## 决策

1. **自研 AXS DSL**（类 Markdown 剧本语言），新包 `packages/axs`。
2. **文本为真相源，节点图为投影**：项目新增 `axs_source` 存储；文本保存 → parse → 覆写 nodes/edges；图编辑 → printer → 重生成文本；冲突时文本优先。
3. **解析只有 TS 单实现**（前端解析，结构化结果提交后端），不做 Python 双端移植——避免两个 parser 漂移。后端新增原子接口 `PUT /projects/{id}/narrative` 接收 `{ axs_source, nodes, edges }`。

## 语法要点（v1 语法冻结面）

```axs
# Beat标题 @stage(舞台名) [key] [ending: 结局名] [if: <条件表达式>]
@bg <image>            @bgm <track> [loop]      @se <sound>
@camera zoom 1.2       @fx rain                 @wait 500
@transition fade 400   @voice <sound>
@flag key = value      @memory key = value      @codex 角色.key = value
角色名: 台词
角色名(表情): 台词
@show 角色 [表情] [位置]    @hide 角色    @move 角色 位置
纯文本行 → 旁白
> 选项文字 -> 目标Beat标题
```

- Beat 由 `#`/`##` 标题行开启；`->` 显式跳转按标题解析为 edge
- 顺序相邻 Beat 之间自动生成默认 edge（无 choice 时）
- 行号 ↔ beat id 位置映射随 AST 输出，供编辑器双向定位
- 目标寻址的完整规则（含同名消歧与序号写法）见下方「补记 2026-09-30」——原文只写「按标题解析」，这一句不足以判定同名标题指向哪一个 Beat，而本轮正是被这个缺口咬到两次

## 质量要求

- parser/printer 100% 单测（引擎级代码标准，同 `packages/core`）
- round-trip 性质测试：`parse(print(beats)) ≡ beats`
- 未知指令行保留为注释透传，不丢内容
- round-trip 必须覆盖**同名 Beat 的两种寻址形态**（裸标题与 `标题-N`），且双向各测一次：图→文本→图不得静默改指（见补记的失败模式）
- **发射器的每一行产物都必须能被解析器读回**（上面第 2 条的推论，2026-10-01 写实）。
  违反过的形状：说话人解不出来的 `say` 被印成 `: 台词`——那一行过不了 `parseDialogueLine` 的 `[^:(]+`，回读整行降级成旁白，
  而冒号会留在玩家看到的文本里。正解是把这种 `say` 按**旁白那一支**印出去，依据是三方一致而不是偏好：
  `packages/core/src/ir.ts:90` 写着 characterId「缺省为旁白」；运行端本来就不显示空说话人的名字
  （`engine.ts::resolveSpeaker` 返回 `null` + `BacklogPanel` 的 `entry.speaker &&`）；文本层没有"无名对白"这个形状。
  Python 那一端在草稿发射时用 `default_speaker` **补一个显示名**（`ai_draft.py:109`），会让玩家多出"旁白"这个名字——
  这是双端差异，已登记进 ADR-027 的补记；本 ADR 采文本可回读 + 播放不变那一条。

## 补记 2026-09-30：目标按 Beat 标题寻址，同名按出现顺序消歧

**为什么现在补**：`-> 目标` 与 `> 标签 -> 目标` 的目标语义在原文只有一句「按标题解析」。标题不唯一时这句话没有判定权，于是「指第二个开场」在文本层根本写不出来——而文本层写不出，就意味着图层的这个指向一旦经过打印就会**静默换靶**。同日修掉的两个缺陷（#68 打印侧丢指向、#69 导入侧 id 复用串号）是同一个缺口的两张面孔，不是两个独立 bug。以下是已生效的契约，代码与测试早已如此，此前只缺这段记录。

**1. 模型层存 id，文本层存可寻址引用，映射只发生在打印那一刻。**
`AxsBeat` 的 `options[].to` 与 edge 的 `to` 存 **beat id**（`packages/axs/src/print.ts:70,222` 把它交给 `idToBeatRef` 按 `b.id` 查）。文本里出现的是标题或序号别名——剧本给人读，id 是给机器稳的。
唯一会让 id 落进正文的情形是**悬空引用**：`idToBeatRef` 在当前 beat 集合里找不到该 id 时原样返回 id（`print.ts:155-156`）。这是刻意的"不丢边"兜底，不是静默——回读时它落在下面第 3 条的无匹配分支，并由 `edges.ts:84`（`跳转目标未找到`）「跳转目标未找到」/ `edges.ts:103`（`选项目标未找到`）「选项目标未找到」报出 diagnostic。所以"id 不进正文"是常规情形的描述，不是绝对保证。

**2. id 由标题按出现顺序生成**（`packages/axs/src/edges.ts:36`（`assignBeatIds`；2026-10-01 从 parse.ts 外提））：
第一个 `开场` → `开场`，第二个 → `开场-2`，第三个 → `开场-3`。即**裸 slug 恒等于第一拍**，其后各拍带 `-N`，N 是出现序号（从 2 起）。

**3. 解析侧的目标解析次序**（`edges.ts:46`（`titleToId`，同上外提））：
标题精确匹配且唯一 → 该拍；标题匹配到多拍 → **确定性取第一拍**（这是刻意保留的规则，不是未定义行为：作者写裸同名标题时，指的就是第一个）；标题无匹配 → 退回 `slugifyTitle(标题)` 查 id，于是 `开场-2` 这类序号别名在此命中第二拍；仍无匹配 → `null`，并报 diagnostic（`:417` / `edges.ts:103`（`选项目标未找到`））。

**4. 打印侧与第 2/3 条共用同一个序号规则**：
标题在全篇唯一时输出裸标题；同名时第一拍输出裸 slug、第 N 拍输出 `标题-N`。这与解析侧的兜底分支严丝合缝——打印出来的每个指向都能被原样读回，这是第 5 条成立的必要条件。

**5. 不变量：`parse(print(g))` 里每条 choice/跳转的靶心不变。**
同名 Beat 是这条不变量唯一的破坏者，因此它是 round-trip 测试的必测形态。
要分清两种失效模式的**可见性**，它们的处置成本完全不同：**换靶**（指向同名第一拍）是静默的——解析不报错、diagnostic 为空、界面照常保存，只有回读后才发现指错了，这是本语言最贵的失效模式（ADR-027 对同类形态的判词是「静默降级比失败更难排查」）；**丢靶**（目标根本解析不出）至少可见，`edges.ts:84`（`跳转目标未找到`）/`edges.ts:103`（`选项目标未找到`） 会报「目标未找到」。补这条契约的动机是前者，后者已经在册。
在册用例三条（不是"应该有测试"的说法，是可以点进去验）：`packages/axs/src/roundtrip.test.ts:136`（choice 形态打印成 `> 向东 -> 开场-2` 并回读成边）、`:180`（裸同名标题确定性指向第一个）、`:203`（显式跳转行 `-> 标题-2`）。

**6. 消费侧的 id 复用同受第 2 条约束**：
AXS 导入到图层时，标题命中既有节点**只在 id 未被本轮用过**的前提下复用（`packages/editor-core/src/axsImport.ts:57-63` 的 `usedNodeIds`；投影侧 `projection/axs.ts:183-193` 同一规则）。否则两个同名桥段会解析出同一个 node id，图上一塌、界面上只剩一个标题——这正是 #69 的成因。门禁两条：界面级 `e2e/desktop-http.spec.ts:785`（E39）与单元级 `document.test.ts:385`（配对判据，同时跑两套实现）。

**未清偿 → 已清偿（2026-10-01）**：裸同名标题「恒指第一拍」是可预测的，但对作者不显眼——写错的第二拍以前不会有任何提示。
现在 `titleToId` 在多命中分支上报一条 warning，文案把该写成的消歧形式直接送到眼前：
「同名 Beat「开场」有 2 处，这里指向第 1 个；要指向第 2 个请写「开场-2」」。
**语义一字未改**（tie-break 仍由同一处代码决定，仍取第一拍），改的只是"要不要说出来"；
出口已有三处（`WriterPanel` 的「N 条提示」列表、`AxsCodeEditor` 的 CodeMirror linter、剪辑台 `MiniAxsEditor`），
severity 为 warning 所以不阻塞保存。上线前量的分母：三份随包 `.axsp` 各含 2 个同名 Beat 标题，
但**裸引用同名的处数为 0** ⇒ 既有作品不会突然亮黄灯。
判据三条：`parse.test.ts`（choice 与 jump 两个调用点各一条 + 唯一标题不许报）、`roundtrip.test.ts`（原「不报诊断」那条断言按新预期改写，**改断言而不是删断言**，它对 id 与 edges 的钉原样保留）。

## 补记 2026-10-01：两处「文本层静默失败」收口，并把条件域外提

同日接着上面那条欠账做了两件事，都是**作者写了、解析器认得一半、结果什么都不说**这一族：

1. **Beat 标题里认不出的方括号**（`# 第二拍 [intro]`）。`[key]` 那类松散分支只认字面量 `key`，
   把键名直接塞进方括号（照本 ADR「`[key: 名称]`」占位写法误读而来）此前走完整个 if-chain 没有任何分支接住：
   不报错、不生效、`key` 保持 `null`。现在补一条 warning，文案直接给出三种可用形式：
   「未识别的 Beat 标记「[intro]」：可用形式是 [key: 名称]、[ending: 名称]、[if: 条件]」。
   **语义一字未改**（不认得仍是不生效），改的只是说出来。上线前量的分母：
   `packages/**` 与 `docs/user/**` 里共 20 处 Beat 标题方括号，**0 处落进新分支**；
   三份随包 `.axsp` 是结构化 JSON、不含 AXS 标题文本，golden 无括号 ⇒ 既有作品不会突然亮黄灯。
2. **条件运算符 `>=` / `<=`**。`COND_OP_RE` 认得这两个记号、`docs/user/writing/axs-syntax.md` 也承诺了它们，
   但 `OP_MAP` 只有 `==`/`!=`/`>`/`<` 四键，缺失分支经 `?? "eq"` 把 `memory.score >= 10` 静默编译成
   `score == 10`——闸门语义从「够 10 就开」变成「恰好等于 10 才开」，且打印回写会把作者原文改成 `== 10`。
   实测证据：修前 `parseCondition("memory.score >= 10")` 返回 `operator: "eq"`（vitest RED 记录的 Received 值）。
   修法是把枚举补齐而不是拒绝：`ComparisonOperator` 加 `gte`/`lte`（`packages/core/src/ir.ts`），
   求值两处跟上（`packages/core/src/conditions.ts` 的 `gte`/`lte` case、
   `backend/app/domains/runtime/service.py::PlayerService._compare` 两条 `elif`——
   该函数对未知运算符返回 `False`，只修 TS 等于在 web 端把闸门永久锁死），
   打印侧 `OP_PRINT` 加 `gte: ">="`、`lte: "<="`。
   判据四条：`condition.test.ts` 映射两支 + 打印原样回到 `>=`（回写不改语义）、
   `conditions.test.ts` 边界断言（`coins=10` 时 `gte 10` 真、`gt 10` 假、`lte 10` 真、`lt 10` 假）。
   Python 那半没有测试覆盖，用 `backend/.venv/bin/python` 直调 `_compare` 实测：
   `10 gte 10 → True / 9 gte 10 → False / 11 gte 10 → True / 10 lte 10 → True / 11 lte 10 → False`。

同轮顺手做的结构清偿：`check:size` 棘轮因第 1 条越线（parse.ts 502 > 493），按门禁自己给的处置**按域外提**——
条件表达式与字面量那一族（`parseLiteral`/`printLiteral`/`parseCondition`/`parseAtomCondition`/`OP_MAP`）
移到 `packages/axs/src/condition.ts`，parse.ts 收到 420 行、棘轮同步收紧。
这一刀和 `./edges` 不同：条件不是 parse 的对外 API，所以**不做转出再导出**，
`./print`、`./index`、测试各自直接指过去（`index.ts` 的公开出口不变）。
对应的测试也搬家：`condition.test.ts` 承接原 `parse.test.ts` 里的两支 describe，断言一条未改。

**同轮把成因也关掉**：`parseAtomCondition` 原来是 `OP_MAP[opStr] ?? "eq"`——缺键时替作者猜语义，且猜的是最不像出错的那个。
现在缺键即整条条件判为不可解析（由既有的 `[if: 条件无法解析]` warning 接住），映射表不再补语义。
配套的不变量在 `condition.test.ts`：记号表直接从 `COND_OP_RE.source` 抽，钉住"词法认得的每个记号都有落点"。
成对变异取数：临时往词法加一个 `=~` 时，新守卫下解析结果为 `null`（不变量红、点名记号表多了一项），
旧兜底下同一条输入得 `operator: "eq"`（探针红在 `to be null` 那一句）——这就是第 2 条那个缺陷的机制本体。
**限度**：这条不变量是绊线不是自动同步；真要加运算符仍须手动过五处清单（`OP_MAP`、TS 求值、Python 求值、`OP_PRINT`、本条文档）。

## 补记（2026-10-01，复审）：消歧写法不是保留命名空间——`标题-N` 会被字面标题占住

上面那条「补记 2026-09-30」定的消歧规则是「同名按出现顺序：第一拍裸 slug，其后 `标题-N`」。
复审实测发现这条规则有一个未登记的漏洞：**`标题-N` 不是一个保留的命名空间**。

- **实测形状**：`# 开场` / `# 开场` / `# 开场-2` 三拍，得到 id `开场` / `开场-2` / `开场-2`
  ——重复 id，且原本「第一拍顺序走到第二拍」的邻接边退化成 `开场-2 → 开场-2` 的**自环**，**零诊断**。
  同形：`# Hello World` / `# hello-world` / `# hello-world-2`。
- **不是新引入**：把 `assignBeatIds` 的计数器键改回去（改前那一行）之后同一组输入照样红。
  它一直是这样，只是没人用这种标题写过东西。
- **为什么不能在实现里顺手修**：`titleToId` 的匹配优先级是**原始标题先、id 后**（见 `edges.ts`）。
  字面标题一旦占住 `标题-N`，那个自动生成的引用就会解析到**字面标题那一拍**——
  也就是说关掉这个洞必须改**消歧方案本身**（换一族标题产生不了的形式，或让字面标题优先/让位），
  而本 ADR 是语法冻结面。所以它是一条**待决**，不是一次实现修补。
- **分母**：随包三份 `.axsp` 的 `axsSource` 是空串（叙事在 `nodes` 里），侧分母 0；
  `docs/**` 的 axs 围栏 + `testdata/axs-draft/*.json` + 测试内联模板串共 33 段、34 条标题，
  slug 撞车 0 处（唯一一处是 `parse.test.ts` 自己的"重复"夹具，属同名那一族）。
  ⇒ 今天没有既有作品会亮灯，加 warning 也是零误报——**但既然修法本身要定档，就不单独加提示**，
  免得把一条还没定的语义先在文本层说死。
- **同轮修掉的是另一格**：`assignBeatIds` 的计数器原先按**原始标题**记，而 id 是拿 **slug** 拼的，
  于是 `Hello World` 与 `hello-world` 这两个**不同标题**共用同一个 slug 时都拿到 n=0 ⇒ id 相同。
  已改为按 slug 记（`parse.test.ts` 三条判据 + 一条往返不变式）。这一格与上面的漏洞**不是同一件事**：
  那条按标题去重是对的、漏的是"不同标题、相同 slug"；本条是按 slug 去重仍留的字面标题占位。

## 后果

- 创作主路径从「拖拽+面板」变为「写作+预览」，画布退为结构鸟瞰
- 散文/MD 导入统一走「规则/AI → AST → printer」流水线
- 未来 `.axsp` 离线包导出（v2.5）可直接内嵌 AXS 源

## 补记（2026-10-09 19:31）：第三处「文本层静默失效」——一拍的第二组分支在发射时丢掉

**现象**：`printBeatBody` 用 `script.find(op === "choice")` 只取第一组分支，第二组连同它的选项一起消失。
界面上没有任何守卫拦住"一拍放两组分支"（`ScriptEditor` 的 `add` 就是 append），所以这条路作者真走得到。
这直接违反本 ADR 的质量要求 `parse(print(beats)) ≡ beats`，而且此前**连一条诊断都没有**——
文本里读不回来的东西，解析侧结构性看不见，只有发射器知道。

**本轮做的只是"说出口"，没有改语义**：`printAxs` 增加可选出参 `options.diagnostics`，
在一拍有多于一个分支组时 push 一条 `warning`（带拍名、总共几组、被丢掉几个选项、以及这一拍在输出文本里的行号），
**输出文本与不带诊断时逐字相同**。另外两条候选（把选项并进第一组＝改叙事语义；扩语法支持多组＝动语法冻结面）
仍留在待决清单里，不由发射器单方面决定。

**判据（`packages/axs/src/roundtrip.test.ts`，`test:unit` 由 774 → 777 passed）**：
一组不响（否则每部正常剧本都带噪音）、两组必响且文本不变、多拍文档里行号要落在真正出问题那一拍。
旧的「第二组不出现在打印结果里」那条特征化断言**保留不改**（它同时是"这条曾经会丢"的凭据；
若定档改成合并或扩语法，要**改写**它而不是删掉它）。
变异两头各见过一次红：删掉那条 `emit` ⇒ 2 条新判据红（14 passed / 2 failed）；
让发射器"顺手"把第二组也印出来 ⇒ 旧特征化断言 + "文本不变"那条一起红，还原后 byte-identical。

**用户能看到的地方**：`MiniAxsEditor`（编排台演出段的 AXS 小编辑器）把这一趟打印收下的诊断与解析诊断合并后一起显示。
**如实登记一条缺口**：这条接线今天只有发射侧单测撑着，没有界面级判据——它不是一个能自发变红的东西，
若有人把合并那一行删掉，`e2e:desktop` 与 gates 都不会响（与 `navigator.clipboard` 那格同例，只登记不占共享定档号）。

## 补记（2026-10-09 20:05）：诊断走到 Writer 主通路，并修掉「重新打开就静默」那一档

**接的是一条出参，不是第二份实现**：`projectToAxs(..., diagnostics?)` → `draftToAxs(draft, roles, diagnostics?)` →
`printAxs(doc, {roles, diagnostics})`。出参一律**可选**，所以既有调用方签名一字未改；文本仍然逐字不变——
本 ADR 的 `parse(print(beats)) ≡ beats` 这条契约管的是**文本**，诊断是旁路，不参与往返。

**界面上有两个时刻需要报，理由不同**（这是同日第八十七／八十八批之间被测量纠正过一次的地方）：

1. **装载**（打开工程）：报的前提是**屏幕上显示的就是这次投影的结果**。判据写成
   `!storedSource || storedSource === text`。前半守住旧结论（存档里躺着 Writer 手写文本时报"投影会丢"是误导）；
   后半是本批新补的一档——**保存过之后再打开，存档里那份文本本身就是上一次写回去的投影**，
   屏幕上少的正是丢掉的那一组，此时静默等于没说。
2. **保存**（`persistAxsProjection` 把投影写回 `axs_source` 的那一刻）：**无条件报**，因为丢失在这一步进存档，
   而装载那一腿当时看到的还是写回**之前**的文本。

**判据**：`E61`（界面级：放两组分支 → 保存 → 顶部出现那条 `role="status"` 常驻说明，链尾零 `/api/v1`）＋
`apps/web/src/features/writer/lib/projection.test.ts` 4 条（无存档文本要说／存档文本＝投影仍要说／手写文本不报且文本不改／投影没丢则静默）。
成对变异各打红**不同的一条**：去掉 `=== text` 那半 ⇒「重新打开仍要说」红；判据整体放开 ⇒「手写文本不报」红。
删掉 `print.ts` 那条 `emit` ⇒ `E61` 红（界面判据吃到最上游出参的证据）。
**为什么两次"删掉一处赋值仍绿"不等于冗余**：那两条腿各守一种存档状态，只测一种状态就会把另一条误读成冗余——
这条读法已在第八十八批作废。

**仍然开着的**：语义修法（把后几组选项并进第一组，或扩语法支持一拍多组）不在本 ADR 单方面决定，留在待决 ⑩。

## 补记（2026-10-10 01:52）：第三个报的时刻——「剧本」tab 那次物化

上一节写的是「界面上有两个时刻需要报」。**那是漏了一个**：装载、保存，还有第三个——**打开「剧本」tab**。

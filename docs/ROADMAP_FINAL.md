## 0. 一句话定位

**Axiforge = 让普通创作者做出明日方舟/命运石之门级作品的 Web 原生叙事平台：**
**创作端是"演出即所得"的无代码 Studio，运行端是"角色会记住你"的 RN Runtime，生态端是角色 IP 可跨作品流转的 UGC 平台。**

三个短语分别对应三条竞争战线，缺一不可，但**有严格的先后**（见 §3）。

## 1. 市场现实（2026-07 核实）与推论

| # | 市场事实 | 对 Axiforge 的推论 |
|---|----------|---------------------|
| M1 | Ren'Py 占约 85% 独立 VN 开发者，靠开源+20 年社区+文档生态形成自增强网络效应；行业报告明确指出"**差异化机会在细分场景，而非与其正面拼通用功能**" | **不做"更好的 Ren'Py"**。全功能对标（§4 能力地图）是长期验收清单，不是近期战场。近期战场是 Ren'Py 结构性做不到的三件事：Web 原生零安装、演出即所得的无代码编辑、角色跨作品 IP |
| M2 | AI 叙事平台竞争已被定义为 "**memory-first**"——"记忆昂贵（算力+工程），但它是用户评判最狠的功能"；能跨会话保持角色关系/世界状态的平台留存显著更高 | **RN 护城河被市场直接验证**。"角色记得你"不是锦上添花，是 2026 年叙事产品的头号留存杠杆。记忆/关系持久层（桥4）优先级上调，必须在 v1.x 内落地而非远期 |
| M3 | AI 辅助创作（立绘生成/剧本草稿/无代码逻辑）正快速成为新平台标配（SEELE、Mimmo、CloudNovel 等）；但行业共识同样明确：**强的系统是"结构约束下的 AI"**（world state + character memory + authored rules），不是无限即兴 | AI 辅助**创作**不能推到 v2.5——但也不必恐慌：我们的六层角色、演出指令集、统一条件系统恰好是 AI 最理想的"结构化落点"。**先建结构，AI 生成填进结构**，后发反而质量更高。AI **运行时**（AI 节点/世界自主 tick）仍然后置 |
| M4 | VN/互动叙事市场 12%+ CAGR 增长；头部 VN 创作者 Patreon 月入 $5k 量级；UGC + 订阅制粘性模型被验证 | 创作者有真实付费与收入动机，UGC 平台闭环（发布→消费→Fork）成立；但**先有 10 份拿得出手的作品，再开市场**——这条 vNEXT 的克制原则保留 |

### 舍弃（糟粕）

| 舍弃 | 理由 |
|------|------|
| vNEXT 的"先打磨现有薄 Player，演出/音频/系统层全推到 Unity 时代" | 给注定重写的东西镀金；高级 VN 的定义性能力（演出）被无限延后，北极星无法被中间产物验证 |
| vNEXT 把 v1.2"记忆驱动"定义为会话内 flag 分支 | 那是所有 VN 引擎都有的普通 flag，市场验证的留存杠杆是**持久**记忆（M2）——名不副实的"记忆驱动"是自我麻痹 |
| "AI 一律 v2.0 之后"的一刀切 | 市场节奏（M3）不允许；正确切分是：**AI 辅助创作**（生成填结构）v1.x 末期即可试点，**AI 运行时**（自主演化）继续后置 |
| "Unity Full Player = 重写引擎"的隐含假设 | 桥1（IR + Compiler）建成后，Unity 只是"再写一个 IR 渲染器"；v2.5 的成本被架构决策直接砍掉一半 |
| 全功能对标 Ren'Py 的隐含焦虑 | M1：正面拼通用功能是死路；能力地图改为"长期逐项点亮"，近期只打三个楔子 |
| `world.py` / `item.py` / `memory.py` 死代码及其代表的"半途构想" | 物理删除；其中正确的意图（世界线/时间线/持久记忆）经由桥4/桥6 以正确架构回归 |

## 3. 战略：三个楔子，一个飞轮

不与 Ren'Py 拼面宽，用三个它结构性做不到的楔子切入，再靠飞轮滚大：

```
楔子1 演出即所得（创作端）      楔子2 角色记得你（运行端）      楔子3 角色 IP 流转（生态端）
  Web 原生、零安装、              持久记忆/关系账本、              角色跨作品复用、Fork、
  时间轴演出编辑、实时预览          存档跨会话、跨作品继承            带着记忆进新作品
        │                             │                              │
        └──────────────┬──────────────┘                              │
                       ▼                                             │
        飞轮：好工具 → 好作品 → 玩家因"被记住"留存 → 创作者因玩家来 → Fork 二创 ←┘
```

**优先级铁律**：楔子1 → 楔子2 → 楔子3，严格按序。演出不成，作品不成立；作品不成立，记忆没有载体；载体不存在，IP 流转是空壳。

## 6. 最终版本路线

> 每个版本 = **加厚一座桥 + 交付一个用户可感知的作品级提升 + 点亮若干能力格**。周期为单人全职估算，宽放 30%。

### v1.1 「脊椎与演出雏形」（约 3 周）—— 建桥1 + 桥2 独木桥

**用户感知**：一个场景能连续演出"角色进场 → 表情变化 → BGM 切换 → 对话 → 选择"，而不是拖 5 个图节点；试玩不再每句话转一次圈。

| 范围 | 内容 |
|------|------|
| `packages/core`（新建，真实存在） | Narrative IR schema（TS + Python 双端）；演出指令集 v0：`say / show / hide / bg / bgm / se / wait / choice` 8 条 |
| 后端 | `player.py` 重构为 **project → IR 编译器**；保留会话持久化与私密条件裁决 |
| Player | 改造为 **IR 渲染器**：加载故事包后本地推进，打字机/分支消费指令流 |
| Studio | 节点内嵌**线性演出脚本编辑器**（列表式 MVP，非时间轴）；Flow 退为场景间流转 |
| 数据 | `narrative_data` 增加 `script: Instruction[]`；旧单句节点自动包装为单指令脚本（兼容迁移） |

**点亮**：D1 两层分离、D2 雏形、D10 地基。
**验收**：同一份 IR 同时驱动 Lite Player 与 headless pytest 跑通同一分支路径；旧项目零手工迁移可玩。

### v1.2 「记忆驱动·真」（约 2 周）—— 建桥3 + 桥4 前两层

**用户感知**：分支由"累积的关系/记忆"驱动；**关掉浏览器再回来，角色还记得你**。

| 范围 | 内容 |
|------|------|
| `packages/core` | 统一条件/效果/表达式系统：typed schema + 双端求值器，替换编辑器与 `player.py` 的三处重复实现 |
| Studio | 条件面板重构接统一 schema；**条件模拟器**（假 memory/关系值 → 预览会走哪条边） |
| 数据 | 记忆分层落地前两层：会话记忆（已有）+ **存档记忆**（`save_slots` 挂 memory/flag/关系值，跨会话存活） |
| Player | 单槽自动存档 + 继续游玩入口 |

**点亮**：D8 持久记忆（市场验证的头号留存杠杆，M2）。
**验收**：条件求值单测覆盖全部类型与操作符；编辑器模拟、编译、运行时三处行为一致；E2E：游玩 → 关闭 → 续玩 → 角色关系值保留。

### v1.3 「演出做透 + 资产管线」（约 3 周）—— 加宽桥2 + 建桥5

**用户感知**：**不写一行代码，做出一段 ≥30 秒、有镜头语言和配乐配音的明日方舟风格演出**。这是楔子1 的成败判据。

| 范围 | 内容 |
|------|------|
| 指令集 v1 | 新增 `move / camera(zoom·pan·shake) / transition / fx(flash·rain·snow) / voice / narration`；富文本与 ruby 注音 |
| 资产管线 MVP | 立绘（含表情差分组）/ 背景 / CG / BGM / SE / 语音 的上传·分类·标签·引用；`show(char, expr)` 直连差分资产 |
| 演出编辑器 | 列表式升级为**分轨视图**（对白轨/立绘轨/音频轨）；**实时预览**（编辑侧即时播放当前脚本）——对标 M1 指出的竞品弱点 |
| Player | 演出运行时：并行指令、转场动画、音频 crossfade、预加载 |
| 工程 | 路由级 code-split；资产 lazy load |

**点亮**：D2 做透、D3 主体、D4 富文本、D9 MVP。
**验收**：官方示范演出（方舟风格 30 秒+）纯编辑器产出；新用户 30 分钟内完成含立绘/BGM 的三场景短篇。

**落地状态（✅ v1.3 收尾完成）**：
- ✅ 指令集 v1（`move / camera / transition / fx / voice / narration` + 富文本 ruby）——core IR/engine + 后端 `ir.py` 镜像 + 单测
- ✅ 表情差分管线（桥5）：`character_data.sprites` 数据层打通 → 编译进 `CharacterRef.expressions`；Character Studio 新增「立绘/表情差分」上传管理 UI；ScriptEditor `show` 表情从该角色差分组下拉选
- ✅ 背景资产：场景资产详情页接入背景图上传，闭合演出背景引用
- ✅ Player 演出运行时：镜头/fx/转场/立绘移动/BGM crossfade/voice/富文本
- ✅ 实时预览：编辑侧内嵌 core 引擎播当前脚本
- ✅ 路由级 code-split
- ⏳ 顺延：**分轨视图**（当前为列表式 + 差分下拉 + 实时预览）与图集/多分辨率优化（ADR-013 定为 v2.0），不阻塞 v1.3 验收目标

### v1.6 「RN 跨作品首秀 + 结构化 AI 辅助」（约 3 周）—— 桥4 第三层 + M3 回应

**用户感知**：**你的角色带着上一部作品的记忆出演新作品**——全市场没有第二家；同时创作端开始有 AI 帮手。

| 范围 | 内容 |
|------|------|
| IP 账本 | 桥4 第三层：角色 Codex（跨作品持久关系/记忆，绑玩家身份，创作者 opt-in 声明哪些记忆可继承） |

| **结构化 AI 辅助**（创作端，非运行时） | ①散文/大纲 → 演出脚本草稿（生成指令序列，创作者审改）②六层角色 AI 填充建议 ③资产 AI 生成对接（立绘/背景 → 直接入资产管线）。全部是"AI 填结构"，结构即质量护栏（M3） |
| ADR | AI 供应商与成本策略单独 ADR |

**点亮**：D8 完整（跨作品）、AI 辅助创作雏形。
**验收**：示范作②的角色进入新剧本后，开场对白因 codex 记忆而不同；一段 500 字散文 → AI 草稿 → 人工修订 → 可播放，全程 <15 分钟。

**落地状态（v1.6 已完成）**：
- ✅ `CodexLedger` IR 类型 + `codex` 条件 / `codex_write` 效果（`@axiforge/core`）
- ✅ 引擎 `RuntimeState.codex` + 播放时读写
- ✅ 后端 `player_codex_entries` + `GET/PUT /play/codex`
- ✅ 编译器输出 `codexScope`（剧本关联角色）
- ✅ Flow 编辑器支持跨作品记忆条件/效果
- ✅ Player 独立加载/同步 Codex（存档槽不持久化跨作品记忆）
- ✅ 示范作②③（缘起·选择 / 再会·记忆）+ 序章·交汇，Codex 跨作品演示
- ✅ AI 辅助创作 MVP：散文→脚本 + 六层角色建议（规则引擎，ADR-015）
- ✅ 工程：删除 `world.py` / `memory.py` / `item.py` 死代码及配套 service/schema

### v1.7 「用户系统贯穿」（约 1–2 周）—— 桥7 后半

**用户感知**：无论在发现页、Studio 还是 Player，右上角都是「同一个人」——创作、游玩、存档、跨作品记忆归属一致。

| 范围 | 内容 |
|------|------|
| 数据层 | `user_accounts` 统一档案：`creator_id` + `player_token` + 可选 `email` / `display_name` |
| API | `POST/GET /users/session` 启动建档；`PUT /users/profile` 更新；`GET /users/resolve` 邮箱恢复 |
| 前端 | `UserProvider` + `useUser()` 全局上下文；`UserAccountMenu` 顶栏账户菜单（Studio / 发现页） |
| 兼容 | 保留 `identity_links` 与轻量邮箱绑定；`identityLink` 同步写入 `user_accounts` |
| 贯穿 | 存档槽、Codex、作品 `author_id`、Fork 血统均消费同一 `creator_id` / `player_token` |

**点亮**：D10 用户层完整、桥7 后半。
**验收**：新设备输入邮箱恢复身份 → Studio 与 Player 数据一致；顶栏显示统一昵称/邮箱。
**仍不做**：密码登录、OAuth、付费账户。

**落地状态（v1.7 已完成）**：
- ✅ `UserAccount` 模型 + session/profile/resolve API
- ✅ `UserProvider` / `useUser()` 全局注入（`App.tsx`）
- ✅ `UserAccountMenu` 顶栏（Studio + 发现页）

## 8. 北极星指标（每版必测）

| 指标 | 定义 | 阶段目标 |
|------|------|----------|
| **TTFP**（Time to First Playable） | 新创作者从注册到发布可玩短篇 | v1.3 ≤ 30 分钟（从模板 v1.5 ≤ 15 分钟） |
| **演出上限证明** | 纯编辑器产出的最佳演出段落质量 | v1.3 起每版一段官方 showcase，对齐方舟水准逐步逼近 |

| **工程底线** | `packages/core` 单测覆盖率 / E2E 数 | core 100%；每版 +1 E2E |

## 9. 风险与止损

| 风险 | 信号 | 止损动作 |
|------|------|----------|
| 桥1 重构拖期（脊椎工程量被低估） | v1.1 超 5 周 | 缩指令集到 4 条（say/show/bg/choice）先通链路，其余移 v1.3 |
| 演出编辑器易用性不达标（楔子1 失败） | v1.3 验收时非作者用户 30 分钟做不出短篇 | 停止加指令，专攻编辑器交互一个迭代；必要时请 3 名目标用户实测 |
| AI 竞品先发抢占"简便"心智（M3 加速） | 头部 AI-native 平台出现演出级输出 | 把 v1.6 的"散文→演出草稿"前提到 v1.4 后立即试点，其余不变——我们的结构化底盘使追赶成本低 |
| Codex 跨作品记忆无人用（楔子3 伪需求？） | v1.6 后 opt-in 率极低 | 保留数据层（成本已沉没在正确架构里），前端收敛为"角色履历"展示功能，等生态密度 |
| 单人产能不足 | 连续两版滑期 >50% | 砍 v1.4 鉴赏子项与 v1.5 作者页，主线（桥1–4）不动 |

## 10. 总纲

> **v5 增补（Cut Studio）**：剧本编辑默认入口升级为 PR 式剪辑工作台（预览 + 时间轴 + 三轨投影），详见 [REFACTOR_CUT_STUDIO.md](./REFACTOR_CUT_STUDIO.md) 与 ADR-022。

> **市场说**：别做更好的 Ren'Py，做 Ren'Py 做不到的事——Web 原生的"演出即所得"，和被 2026 市场验证为头号留存杠杆的"角色记得你"。
> **架构说**：先立脊椎（IR），每版加厚一座桥，让 Lite Player 的每一分打磨、未来 Unity 的每一个渲染器，都消费同一份地基。
> **节奏说**：v1.1–v1.6 六个版本，每版一座桥、一个可感知的作品级提升、一批点亮的能力格；AI 填结构而非替代结构；UGC 在内容之后，变现在生态之后。

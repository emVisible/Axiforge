# ADR-025：AXS 与剪辑台对等双视图（修订 ADR-016「文本优先」）

**状态**：已采纳（修订 ADR-016）
**日期**：2026-08-26
**关联**：ADR-016、ADR-022、ADR-024

## 背景

ADR-016 定「文本为真相源，冲突时文本优先」。ADR-022 之后剪辑台成为默认主视图，该策略产生系统性覆盖风险：剪辑台每次 `saveAll` 都以 printer 整篇重生成 `axs_source`，手工精修的文本被静默覆盖。

代码调查证实：剪辑台与 AXS 数据层本就相互独立（软镜像关系）——剪辑台零 import `packages/axs`，持久化主通道是结构化 nodes/edges，文本权威仅在 Writer 轨保存瞬间成立。「文本优先」的全局地位与实际工作流不符。

## 决策

1. **对等双视图**：剪辑台与 AXS 是同一 Draft 的平级投影，废除全局真相源优先级。
2. **最后编辑者权威**：冲突判定改为按编辑事件排序——任一侧编辑（script 变更 / Writer 保存）置 dirty 标记并记序；另一视图进入时增量同步而非整篇覆盖。
3. **行级锚点替代整篇重生成**：利用 parser 已有的 line↔beat 映射升级为指令级锚点（片段 ⇄ AXS 行号双向索引），支持局部精修与最小 diff 写回。
4. **`axs_source` 保留持久化**，定位由「真相源」改为「可版本化的文本投影快照」（diff 友好、可导入导出）。

## 后果

- ✅ 剪辑台主工作流不再有隐性覆盖
- ✅ 为「片段⇄文本双向定位」（融合方向 F1）提供机制基础
- ⚠️ 同步复杂度上升（dirty 追踪 + 锚点稳定性）；round-trip 单测须扩展为「剪辑态 ↔ 文本」一致性测试
- ⚠️ `docs/user/writing/axs-syntax.md` 中「文本为真相源」等用户侧表述需在落地时同步更新

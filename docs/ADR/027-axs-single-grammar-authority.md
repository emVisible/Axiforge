# ADR-027：AXS 语法单一权威（废除 `【】` 方言与第二解析器）

**状态**：已采纳
**日期**：2026-09-25
**关联**：[ADR-016](./016-axs-narrative-language.md)（AXS 文本为真相源）、[ADR-015](./015-ai-assisted-creation.md)（规则优先 + 可选 LLM）、[ADR-020](./020-llm-multi-provider-local-first.md)、[ADR-025](./025-axs-peer-dual-view.md)、[ADR-024](./024-desktop-local-first.md)、执行件 `BLUEPRINT_v1.0.md`、[REFACTOR_DESKTOP](../REFACTOR_DESKTOP.md) Phase 9 前置

## 背景

v1.0「演绎内核」要做的是把散文/粗写转成 AXS 演出脚本的 AI 通路接进产品。取证时发现后端这套能力**几乎已经建完**：`AiProvider` 定义了 `prose_to_axs`（`backend/app/domains/llm/provider.py:23`），`rules` / `ollama` / `openai_compat` 三个 provider 全部实现了它，`llm/service.py:72` 还带 `_run_with_fallback` 的来源归因。缺的只有路由——`llm/router.py` 目前只有 `@router.get("/health")` 一条。

也就是说，「接上就能用」看起来只差一个端点。但**它产出的不是 AXS**：

| 事实 | 证据 |
|---|---|
| canonical 语法由 ADR-016 规定为 `@` 前缀指令，且明确「纯文本行 → 旁白」 | `docs/ADR/016-axs-narrative-language.md:21,27,28`；该文件内 `【` 出现 **0 次** |
| `packages/axs` 的实现与 ADR-016 一致 | `parse.ts:234-318`（12 条指令）、`print.ts:85-140`；`parse.ts` 内 `【` 出现 **0 次** |
| 规则引擎发射的却是中文括号方言 | `ai_draft.py:99` `【背景 x】`、`:101` `【音乐 x】`、`:108` `【转场 fade】`、`:110` `【特效 flash】` |
| 提示词还**教模型**输出这套未授权方言 | `prompts.py:30`「可用【背景】【音乐】【转场】等舞台指令」 |
| 且它是第二个 AXS 解析器 | `ai_draft.py:127-141` `axs_to_script()` 自剥 `*…*`（`:137-138`）、自跳 `#`（`:135-136`）、复用散文正则 |

关键的后果不是「解析失败」，而是**静默降级**。canonical 解析器的分派顺序是：`@` 前缀走指令（`parse.ts:540`）、`\` 前缀走转义旁白（`:553`）、含 ASCII 冒号走对白（`:559`），**其余一律当旁白文本**（`:568`）。因此：

- `【背景 教堂】` → 变成旁白，字面的中文括号被读给玩家听；
- `角色：台词`（提示词教的全角冒号，对白正则 `parse.ts:334` 只认 ASCII）→ 整行变旁白，**说话人丢失**；
- `*旁白文本*`（`ai_draft.py:97` 的旁白发射形态）→ 星号留在正文里。

三条都不产生 diagnostic。把这条通路接出入口，等于往作者的文本真相源里持续灌入会静默变形的脏文本。

## AXS 方言对照表（逐指令，行号可点验）

规范出处：[ADR-016](./016-axs-narrative-language.md) `:21,27,28`。解析 `packages/axs/src/parse.ts`，发射 `packages/axs/src/print.ts`，规则引擎 `backend/app/domains/narrative/ai_draft.py`，提示词 `backend/app/domains/llm/prompts.py`。

| 语义 | canonical（解析 / 发射） | `ai_draft` 读 → 写 | `prompts` 教给模型 | 差异后果 |

| 背景 | `@bg <image> [transition]` / parse `:234-243`、print `:85-86` | 只认 `【背景】` `:10,45-46` → 写 `【背景 x】` `:99` | 「【背景】」`:30` | 括号形态落入 parse `:568` 兜底 → **变成读给玩家的旁白** |
| 音乐 | `@bgm <track> [loop]` / `:244-248`、`:87-90` | `【音乐】` `:47-48`，`loop` **硬编码 True** → 写 `【音乐 x】` `:101` | 「【音乐】」 | 同上；且 loop 不可表达为 false |
| 音效 | `@se <sound>` / `:250-251`、`:92` | **读写两侧均无此形态**（解析器根本不产生该 op） | 未教 | 若 op 由别处流入，发射会落 `:111-112` 的 text 兜底；当前是永久缺席 |
| 语音 | `@voice <sound>` / `:252-255`、`:94` | **无** | 未教 | 同上 |
| 等待 | `@wait <ms>` / `:256-258`、`:96` | **无** | 未教 | 同上 |

| 跳转 | `-> 目标` / parse `:378-381` | **无** | 未教 | 分支出口不可生成 |

| 解析器份数 | 一处：`packages/axs/src/parse.ts` | **两处**：`axs_to_script()` `:127-141` 另立一套归一化 | n/a | ADR-016 的「文本为真相源」在 Python 侧被复制成第二套语义 |

结论：12 条 canonical 指令里，规则引擎**只覆盖 5 条**（背景/音乐/旁白/转场/特效），且这 5 条的书写形态全部与 canonical 不兼容；对白与旁白的发射形态一处兼容、一处不兼容。所以问题不是"差一个端点"，是"接上就变形"。

## 决策

**1. canonical 语法的唯一权威 = ADR-016 的规范文本 + `packages/axs` 的实现。** `ai_draft.py` 停止产出 `【】` 方言，`prompts.py` 改教 canonical 语法。方言不进入 canonical 解析器。

**2. 演绎内核的真相源落在 TS，Python 只保留远程模型适配壳。** 散文→指令序列的规则实现归 `packages/axs`；`axs_to_script()` 这个第二解析器废除。双端等价由**一份共享 golden 向量**（`testdata/axs-draft/*.json`：输入散文 → 期望 canonical 文本）约束，两端 runner 各跑同一批——沿用编译器 TS/Python golden 已验证过的机制形态（`packages/core` golden 6/6）。向量只描述「输入→输出」，任何一端不得把向量内容当实现复制。

**3. AI 产物只进建议面，作者采纳才落文**，采纳动作经既有 Transaction/Journal（单步 undo 回到采纳前字节）。理由：ADR-016 承诺文本是真相源，而宪章要求「文本可为真相源时须写明冲突策略」。

**4. 桌面纯离线必须有下限：`rules` 独立成拍**（至少一条 `say` 加一条舞台指令），且该断言必须在 node 测试中可执行——桌面本地支在 Playwright 下结构上不可达（`isTauriEnvironment()` 恒 false），这是上一版已经栽过的判据形态。

## 备选与否决

- **B：两种方言长期共存，中间加翻译层。** 否决——同一语义两个真相源（铁律 4）。此后每加一条指令要同步 parser / printer / ai_draft / prompts 四处，漂移不是偶发事故而是必然复发。
- **C：让 canonical 解析器也接受 `【】`。** 否决——`纯文本行 → 旁白`（`parse.ts:568`）是 ADR-016 定下的设计基线，不是缺陷。接纳 `【】` 会把「未识别内容静默变旁白」这个既有失效模式**升格为正式语法**，从此无法区分「作者写的旁白」与「舞台指令没被认出来」。
- **D：先只做后端端点，语法统一以后再说。** 否决——产物不可解析即静默变形，先接等于先放大缺陷。这正是本版把 M1 定为方言统一而非接模型的理由。
- **E：改 `parseDialogueLine` 让它也认全角冒号。** 本轮否决——它会把「作者手滑写全角」静默变成对白。正确形态是给一条 lint **诊断**（warning）而非静默接受；登记为未清偿欠账。

## 后果

**正面**：AI 通路第一次产出可被解析的合法 AXS；离线 rules 通路有了可验证的下限；第二解析器废除，AXS 语法回到一处定义。

**代价与欠账（不在本版假装清掉）**

1. `ai_draft.py` 的方言只有 5 种舞台形态（背景/音乐/旁白/转场/特效），canonical 有 12 条指令。`@se` `@voice` `@wait` `@camera` `@show` `@hide` `@move` 与 `->` 跳转在规则路径上**完全缺席**——其中 `@camera`（镜头语言）正是「演出上限」最吃的一层。M1 不承诺离线也能出镜头，这部分要等 TS 内核补齐。
2. 现存硬编码语义：`bgm` 的 `loop=True`（`:48`）、`transition` 的 `ms=500`（`:52`）、`fx` 的 `ms=600`（`:54`）。迁移时默认**保留现值**，不同步参数化——否则一次方言修复会顺带改演出语义（铁律 3 单维度变更）。
3. 若存量 `.axs` 文本或随包 `.axsp` 里已有依赖 `【】` 的写法，它们在 canonical 下本来就被当旁白，故停发方言**不改变既有读取结果**；但该前提要在改发射器前实测确认（扫描面须显式交代）。
4. 全角冒号导致的静默旁白仍是作者体验陷阱，按决策 1 不靠放宽解析解决，另立 lint 诊断欠账。
